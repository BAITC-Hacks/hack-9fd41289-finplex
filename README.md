# Автоматический расчёт заказов поставщикам для пополнения склада

## 1. Краткое описание

**Проблема:** Менеджер отдела закупа вручную консолидирует данные в Excel для расчёта потребности в пополнении склада, что приводит к избыточным запасам по одним позициям и дефициту по другим. Разовые крупные заказы искажают расчёт регулярной потребности, вызывая лишние издержки и упущенные продажи.

**Решение:** Сервис автоматически рассчитывает рекомендуемые заказы поставщикам на основе:
- Истории продаж с выявлением и исключением разовых крупных заказов
- Анализа сезонности и устойчивого роста спроса
- Текущих остатков и товаров в пути
- Оценки упущенного спроса в периоды дефицита

**Для кого:** Менеджер отдела закупа ТОО «Электрокомплект»

## 2. Что реализовано

### Основные функции (реализовано):

- [x] **Расчёт базовой потребности** — анализ истории продаж, остатков, товаров в пути и категорий товаров
- [x] **Прогнозирование спроса** — учёт сезонности и устойчивого роста спроса
- [x] **Компенсация дефицитов** — оценка и коррекция упущенного спроса при stockout
- [x] **Фильтрация выбросов** — автоматическое выявление и исключение разовых крупных заказов (детект по z-score)
- [x] **Формирование заказов** — группировка по поставщикам с обоснованием каждой позиции
- [x] **Дашборд** — веб-интерфейс: KPI, график спроса/прогноза, таблица заказов, экспорт CSV
- [x] **AI-резюме** — LLM-сводка для менеджера (OpenAI-совместимый провайдер, с fallback без ключа)

> Работает на реальных данных партнёра (Systeme Electric): 497 товаров, 77k+ строк продаж.

### Опциональные возможности:

- [ ] Приоритизация позиций по риску дефицита
- [ ] Учёт минимальной партии заказа и условий поставщика
- [ ] Визуализация трендов спроса по категориям
- [ ] Интеграция с внешними системами учёта

## 3. Как работает решение

### Основной сценарий:

1. **Вход данных:**
   - История продаж (дата, артикул, количество, обезличенный ID клиента, цена)
   - Текущие остатки по складам
   - Сведения о товарах в пути
   - Периоды отсутствия товара (stockout)
   - Справочник поставщиков и сроков поставки
   - Материальная ведомость

2. **Обработка:**
   - Анализ трендов продаж и выявление сезонности
   - Исключение аномалий (разовые крупные заказы)
   - Прогноз потребности на следующий период
   - Оценка упущенного спроса в периоды дефицита
   - Расчёт рекомендуемого количества по каждому артикулу

3. **Выход:**
   - Список рекомендованных заказов: артикул → поставщик → количество → обоснование → срочность
   - Группировка по поставщикам
   - Объяснение расчёта для каждой позиции

4. **Утверждение:**
   - Менеджер проверяет и корректирует рекомендации
   - Формирует окончательный заказ
   - Экспортирует в поддерживаемый формат

## 6. Установка и запуск

### Требования:
- Python 3.8+
- pip или conda

### Запуск (актуальный)

Данные партнёра уже в `data/`. Нужен Python 3.11+.

**Бэкенд (API):**
```bash
cd backend
python -m venv .venv
.venv\Scripts\activate            # Windows;  Linux/Mac: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --port 8020
```
API: http://localhost:8020  ·  проверка: http://localhost:8020/health

**Фронтенд (дашборд):**
```bash
cd frontend
python -m http.server 3100
```
Открыть http://localhost:3100 → выбрать поставщика → «Рассчитать».

**LLM (опционально):** создать `backend/.env` с `LLM_API_KEY=...` (OpenAI-совместимый).
Без ключа AI-резюме работает по шаблону — приложение полностью функционально.

### Структура (актуальная)

```
backend/
  app/
    main.py            # FastAPI: /health, /api/suppliers, /api/plan
    config.py          # настройки (env), параметры расчёта
    llm.py             # LLM-обёртка + fallback
    datasets.py        # реестр наборов данных партнёра
    core/
      loader.py        # чтение Excel-выгрузок 1С (витрина, история, MOQ)
      planner.py       # ЯДРО: расчёт заказов, детект выбросов, сезонность, stockout
  requirements.txt
frontend/
  index.html, styles.css, app.js   # дашборд (KPI, график, таблица по поставщикам)
data/                  # реальные данные партнёра (Systeme Electric, ИЭК)
```

## 7. Как проверить решение

### Сценарий 1: Базовая потребность

**Данные:** 3 артикула, история продаж за 12 месяцев, текущие остатки, информация по поставщикам

**Ожидаемый результат:**
- [ ] Система выдала рекомендации по всем артикулам
- [ ] Каждая рекомендация содержит обоснование
- [ ] Изменение входных данных (например, остатков) отражается на результате

**Команда:**
```bash
python -m pytest tests/test_order_calculator.py::test_basic_demand_calculation -v
```

---

### Сценарий 2: Сезонность

**Данные:** Артикул с выраженной сезонностью (пиковые месяцы — июль-август)

**Ожидаемый результат:**
- [ ] Прогноз для июля выше, чем для января
- [ ] Рекомендуемое количество отражает сезонный паттерн

**Команда:**
```bash
python -m pytest tests/test_demand_forecasting.py::test_seasonality -v
```

---

### Сценарий 3: Исключение выбросов

**Данные:** В историю добавлен разовый заказ (в 10 раз больше среднего)

**Ожидаемый результат:**
- [ ] Рекомендуемое количество не выросло существенно
- [ ] Выброс идентифицирован и исключён

**Команда:**
```bash
python -m pytest tests/test_anomaly_detection.py::test_large_order_detection -v
```

---

### Сценарий 4: Компенсация дефицита

**Данные:** История с периодом stockout, затем восстановление продаж

**Ожидаемый результат:**
- [ ] Потребность скорректирована в большую сторону
- [ ] Размер коррекции обоснован

**Команда:**
```bash
python -m pytest tests/test_demand_forecasting.py::test_stockout_compensation -v
```

---

### Полная проверка:

```bash
# Запустить все тесты
pytest tests/ -v --cov=src

python src/order_calculator.py --sales-file data/sample_sales.csv \
```

## 8. Данные и интеграции

### Входные данные:

| Источник | Формат | Описание |
|----------|--------|---------|
| История продаж | CSV / API | Дата, артикул, кол-во, обезличенный ID клиента, цена, склад |
| Текущие остатки | CSV | Артикул, склад, количество на дату |
| Товары в пути | CSV | Артикул, кол-во, дата ожидаемой доставки |
| Периоды дефицита | CSV | Артикул, дата начала, дата окончания stockout |
| Справочник поставщиков | CSV | Поставщик, артикул, сроки поставки, минимальная партия |
| Материальная ведомость | 1С / CSV | Артикул, категория, характеристики |

### Анонимизация данных:

- Все идентификаторы клиентов заменяются на хэши или анонимные номера
- Сохраняется информация о количестве покупок, но не о персональных данных
- Система не хранит информацию о конкретных клиентах

### Внешние сервисы:

- Интеграция с 1С (опционально, API или прямой импорт)
- Экспорт в внешние системы (опционально)

## 9. Ограничения

### Текущая версия:

- [ ] Не поддерживается автоматическая рассылка заказов (только экспорт и визуализация)
- [ ] Требуется ручное утверждение менеджером перед отправкой заказа
- [ ] Горизонт прогноза — [указать период]
- [ ] Минимальный период истории для надёжного прогноза — [указать месяцы]

- Интеграция с системой управления поставками в реальном времени
- Автоматическая оптимизация по затратам доставки
- Поддержка многоуровневых цепочек поставок
