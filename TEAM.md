## Работа втроём

1. Каждый работает со своим GitHub-аккаунтом и собственными `git user.name`/`git user.email`; используйте подтверждённый email или GitHub noreply. Не подменяйте авторство и даты.
2. Сначала получите актуальную main, затем создайте отдельную ветку в этом же репозитории. Делайте содержательные коммиты и PR; обычный merge сохраняет историю авторов. Не используйте force-push в общей main.
3. Для старого клона, основанного на 67a24f7, сначала сохраните неопубликованные изменения. Если история расходится, безопаснее создать свежий clone в другой папке и перенести только ещё не опубликованные правки; не выполнять слепой reset с потерей файлов.
4. По итогам каждого часа сохраняйте реальный промежуточный результат в репозитории. Коммит может содержать код, тестирование, данные, дизайн или документацию. Квоты push на каждого участника в предоставленном регламенте нет; пустые коммиты не подтверждают работу.
5. Перед сдачей один участник проходит [проверку запуска](docs/ACCEPTANCE.md) на другом ноутбуке. Итоговая версия должна быть опубликована до 18:00 по Астане 23.09.2026 и подана по инструкции организатора. Наличие push не заменяет подачу.

AI-помощь и происхождение компонентов раскрыты в [THIRD_PARTY.md](THIRD_PARTY.md). Сведения об иных инструментах и фактических результатах участники добавляют по мере работы.
