# Проверка чистого запуска перед сдачей

Выполнить на втором ноутбуке из свежего клона предоставленного организатором репозитория. Не использовать существующую venv или рабочую БД. Не публиковать реальные ключи и персональные данные. Доступ к приватному репозиторию организатора нужен для клонирования; для самого расчёта личные платные аккаунты не нужны.

## Установка и запуск

1. Записать `git rev-parse HEAD`, ОС и способ запуска.
2. Для Docker нужны работающий Docker Engine и Compose v2; первый build скачивает базовые образы и зависимости. Из корня выполнить `docker compose up --build`. Дождаться healthy backend.
3. Без Docker следовать README: Python 3.11–3.12, новая venv, установка requirements-dev.txt, отдельные процессы Uvicorn и HTTP-сервера. Нужен доступ к индексу Python-пакетов при установке.
4. Открыть http://localhost:8020/health и http://localhost:3100. Ожидание: health со status=ok; оба поставщика доступны. LLM_ENABLED оставить false.

## Основной сценарий

1. Рассчитать Systeme с пустым сроком «Из данных». Проверить дату источников, объяснения, предупреждения, количество, поставщика и срочность.
2. Ввести общий срок, пересчитать, затем очистить и пересчитать: автоматический режим восстановлен. Индивидуальные сроки проверяются также API-регрессией `test_http_automatic_lead_preserves_item_terms_and_manual_override`.
3. Выбрать товар с известной ценой, изменить количество с соблюдением партии, сохранить черновик. До утверждения экспорт недоступен. Указать ответственного, подтвердить проверку данных и утвердить. Скачать CSV: только выбранные строки и утверждённые количества.
4. Перезапустить сервер без удаления volume/БД. Открыть сохранённый заказ и повторить экспорт.
5. Рассчитать ИЭК. Проверить предупреждения о ценах и остатках. Для демонстрационного черновика ввести явно тестовую цену; не выдавать её за цену партнёра. Заказы поставщикам сервис не отправляет.
6. Проверить сценарии спроса и задержки. При автоматическом сроке задержка добавляет 0,5 месяца к сроку каждого товара.

## Проверки разработчика

Из backend: `python -m pytest`, `ruff check app tests`. Из корня: `node --check frontend/app.js`, `node --test frontend/tests/parameters.test.cjs`, `docker compose config --quiet`.

Тесты stockout и обезличенного клиента используют маркированные синтетические значения в backend/tests/test_regressions.py; реальные исходные файлы этих полей не предоставляют. Тесты не доказывают экономию и совместимость с конкретной обработкой 1С. Не заявлять полноценный расчёт по каждому складу: текущий набор сводный.

## Запись результата

Проверяющий добавляет фактические SHA, ОС, версии Python/Docker, команды, результат каждого шага и обнаруженные ошибки. До выполнения нельзя отмечать чистый запуск пройденным. Проверка Compose-конфигурации не равна сборке и запуску контейнеров.
