# Данные отдельных складов

Расчёт по конкретному складу включается после предоставления его данных. Сводка партнёра сама по себе не позволяет определить остатки каждого склада. Система не делит сводные остатки пропорционально продажам.

## Подготовка и загрузка

1. Получите выгрузку из 1С и преобразуйте её в контракт `warehouses.json`, описанный ниже. Это адаптер входных данных, не подключение к серверу 1С.
2. Из каталога `backend` проверьте файл: `python -m app.warehouse_data ПУТЬ_К_ФАЙЛУ`. Проверка не изменяет исходные данные. Используйте окружение с установленными requirements.txt.
3. Поместите проверенный файл в `data/systeme/warehouses.json` или `data/iek/warehouses.json` соответствующего поставщика. При загрузке дополнительно проверяется наличие кодов в его справочнике. Заменяйте файл целиком, желательно атомарным переименованием временного файла.
4. Обновите страницу: склады появятся в списке. Для обновлённого кода требуется один раз пересобрать контейнеры через `start.cmd`. Следующие изменения файла подхватываются через смонтированный каталог без пересборки.
5. Выберите склад и рассчитайте заказ. Изменение входного файла делает ранее созданные неутверждённые планы устаревшими: нужен новый расчёт. Уже утверждённые заказы сохраняют исходные значения.

Неверный файл вызывает объяснимую ошибку загрузки набора, а не молчаливый расчёт по сводке. Уберите или исправьте файл, чтобы восстановить расчёт. Файлы содержат коммерческие данные: не публикуйте реальные выгрузки в открытом репозитории.

## Контракт v1

Пример **синтетический**: не копируйте его как реальные остатки. Код `DEMO-001` должен быть заменён существующим кодом номенклатуры поставщика.

```json
{
  "schema_version": 1,
  "as_of": "2026-09-22",
  "warehouses": [{
    "name": "Склад Астана",
    "items": [{
      "code": "DEMO-001",
      "stock": 20,
      "reserved": 5,
      "cost": 150.50,
      "lead_time_days": 30,
      "growth_coef": 1.1,
      "monthly_sales": {"2026-06": 40, "2026-07": 35, "2026-08": 45},
      "stockout_days": {"2026-08": 5},
      "transit_lots": [{"qty": 10, "eta": "2026-09-30"}]
    }]
  }]
}
```

- `as_of`: дата, на которую подтверждены физические остатки и резервы.
- `code`: строковый код 1С; ведущие нули сохраняются. Дубликаты внутри склада запрещены.
- `stock` и `reserved`: физический остаток и резерв в единицах справочника. Оба обязательны; резерв не больше остатка. Свободный запас = stock − reserved. Если выгрузка уже содержит свободный запас, не вычитайте резерв второй раз.
- `monthly_sales`: продажи **этого склада**, все последовательные полные месяцы до месяца as_of. Все товары одного склада имеют одинаковое окно; явный ноль означает подтверждённое отсутствие продаж. Пропуски запрещены. Для годовой сезонности передавайте 24 месяца, когда они доступны; три месяца примера недостаточны для подтверждения годового паттерна.
- `transit_lots`: обязательный список, `[]` означает подтверждённое отсутствие товаров в пути. ETA должна быть позже as_of; просроченные поступления сначала сверяются. В расчёт потребности входят поступления внутри срока поставки; более поздние не покрывают ближайшую потребность.
- `stockout_days`: подтверждённое количество дней отсутствия товара за месяц. Нулевые продажи не считаются доказательством stockout. Не передавайте периоды без подтверждения.
- `cost`: закупочная цена в KZT, минимум 1. Если неизвестна, опустите; менеджер укажет её перед утверждением.
- `lead_time_days`: срок товара в днях, до 365. При отсутствии используется срок поставщика с предупреждением.
- `growth_coef`: дополнительный прогноз прироста, по умолчанию 1. Исторический устойчивый рост рассчитывается отдельно.

Поля с ФИО и иными реквизитами клиентов запрещены строгой схемой. В расчёт аномалий сделок попадают только накладные исходной истории с точно совпадающим названием склада; используются обезличенные ID, если они присутствуют. При отсутствии накладных доступны лишь месячные аномалии с предупреждением. Сезонный профиль рассчитывается по выбранному складу, без подмешивания сводного спроса.

Пустой выбор «Сводный расчёт» продолжает использовать оригинальную сводку. Склады не складываются со сводкой и друг с другом. Складской файл может содержать часть ассортимента — расчёт охватывает только перечисленные позиции, что указано в предупреждении. Автоматические перемещения между складами не реализованы.
